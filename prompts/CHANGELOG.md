# Версії промпту

## v1 — базова лінія

Мінімальний промпт: дослівне копіювання, null замість вигадування, крапка як десятковий роздільник.
Мета — виміряти, що модель робить «з коробки».

## v2 — правила під помилки v1

Кожне правило виправляє помилки, знайдені в `results/haiku__v1__t0/errors.md` (Haiku, temperature 0, 10 golden-чеків).
Правила, на які в v1 не знайшлося помилок (сет-меню, бонуси як позиції), з v2 прибрано.

| Правило v2 | Помилка v1 | Скільки |
|---|---|---|
| Рядок «к-сть X ціна» стоїть перед назвою, приклад з розбором | qty = 1 і unit_price = null для вагових товарів; у azk_11 переставлені qty, ціна і сума | 4 позиції у 3 чеках (super_01, azk_04, azk_11) |
| Літера після суми — vat_group позиції | vat_group = null або чужа літера | 7 позицій у 4 чеках (azk_11, food_01, azk_04, fop_01) |
| total повторюється в кількох рядках, бери те, що повторюється | total = 688 замість 2065.60, 131 замість 731.00 (OCR зіпсував рядок СУМА) | 2 чеки (azk_01, azk_11) |
| seller.name — юрособа / ФОП, не назва магазину | «Наркетопт» замість «ФО-П Федик О.Б.»; «ТОВ … і магазин BRAIN» | 2 чеки (fop_01, shop_01) |
| Назва разом з артикулом на початку | артикул відкинуто | 9 позицій у 2 чеках (fop_01, shop_02) |
| ЗН — не fiscal_number | fiscal_number = «ТНа001074017» (заводський номер) | 1 чек (fop_02) |
| Знижка під позицією — discount (уточнено прикладом) | неправильна знижка на рядок | 3 позиції (fop_01) |
| discount_total = null, якщо рядка знижки немає | discount_total = 0 | 1 чек (azk_11) |
| Час через дефіс «17-35-20» | час = 00:00 | 1 чек (fop_02) |

Помилки, які промптом не виправити, бо їх джерело — OCR, а не модель:
- реквізити ПН / ІД / ФН / № чека missed, бо OCR знищив рядок (azk_01, azk_11);
- спотворені цифри: 363052623016 замість 383053623016, рік 2028 замість 2026, q64DxalJXX0 замість q64Dxa1JXX0.
