# Receipt Extractor — ДЗ 1 курсового проєкту

Витягування структурованих даних з чеків для авансових звітів і порівняння платної моделі з локальною.

**Курсовий проєкт:** фото чека → OCR → JSON за схемою (ДЗ 1) → RAG по положенню про відрядження → агент перевіряє ліміти й дублікати та готує чернетку авансового звіту → сервіс з API і моніторингом.

## Запуск однією командою

```bash
cp .env.example .env      # необов'язково: без ключа платна модель пропускається
ollama pull qwen3:4b-instruct-2507   # необов'язково: без Ollama локальна модель пропускається
make run
```

`make run` ставить залежності (`uv sync`), проганяє доступні моделі за матрицею з `configs/experiments.yaml` і оновлює `REPORT.md`. Якщо жодна модель недоступна, звіт будується з закомічених `results/`. Повторний запуск не платить за вже зроблені виклики: відповіді кешуються в `.cache/`.

Ollama на окремому сервері: прокинь порт SSH-тунелем і лиши `OLLAMA_BASE_URL=http://localhost:11434`:
`ssh -N -L 11434:localhost:11434 user@ollama-host`. Відкривати 11434 в інтернет не можна: в Ollama немає автентифікації.

Windows без `make`: `.\make.ps1 run` (ті самі цілі, що в Makefile).
Без `uv`: `pip install -e . && python -m extractor run`.

## Що де

| Шлях | Що там |
|---|---|
| `data/texts/` | OCR-тексти чеків як віддав tesseract, з замаскованими ПД |
| `data/golden/` | Ручна розмітка 10 чеків |
| `data/ocr_config.json` | Версія і налаштування OCR |
| `src/extractor/schema.py` | Pydantic-схема `Receipt` |
| `src/extractor/providers.py` | Ollama / Anthropic / OpenAI-сумісний за одним інтерфейсом; retry з backoff і Retry-After |
| `src/extractor/runner.py` | Матриця експериментів, re-ask при невалідному JSON, кеш |
| `src/extractor/metrics.py` | Точність по полях, вигадані значення, позиції, ПДВ, арифметика кодом |
| `prompts/` | Версії промпту і `CHANGELOG.md` з причинами змін |
| `results/<model>__<prompt>__<sampling>/` | `meta.json`, `calls.jsonl`, `outputs/`, `metrics.json`, `errors.md` |
| `REPORT.md` | Звіт: авто-таблиці + розбір помилок і вибір |

## Ключові рішення

- **Невалідна відповідь:** транспортні збої (timeout, 429, 5xx) повторюються з exponential backoff; невалідний JSON — один re-ask з текстом помилки Pydantic, далі `status: failed`. Токени і вартість рахуються по всіх спробах.
- **Пропущені поля:** у схемі `null`, а не вигадане значення. Частка вигаданих значень рахується окремо від помилок.
- **`category`** — класифікація, а не витягування: окрема метрика, не входить у «вигадані значення».
- **Арифметику перевіряє код:** сума позицій = total, qty × ціна = сума рядка, ПДВ = ставка. Базова лінія — golden, щоб не штрафувати модель за розбіжності каси.
- **qwen3:** `think: false` явно; `thinking_chars` логуються в `calls.jsonl` і мають бути 0.
- **Prompt injection:** текст чека передається в тегах `<receipt_text>` як дані.
